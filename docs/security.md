# Security and privacy

- Document and frontend buckets block all public access, use bucket-owner-enforced ownership, SSE-S3 encryption, and deny non-TLS requests. CloudFront origin access control reads only frontend objects. Documents are not served through CloudFront.
- API Gateway validates Cognito access tokens and route scopes. The handler additionally checks token type/client/user identity and optional group membership. The webhook route alone bypasses Cognito and verifies the raw-body HMAC instead. HTTP CORS preflight is handled by API Gateway.
- A reused Cognito pool can contain users from other applications. Set `required_group` to restrict this application's users; all members have the same read/sync/download access. A newly created pool permits only administrator-created users. Existing pool settings are preserved, so review its enrollment/password/MFA policies separately.
- Amplify manages sessions, refresh, and sign-out using session storage. No client secret is used. Signed document links are bearer capabilities for at most 15 minutes; avoid sharing them. Logout does not revoke already-issued signed URLs. CSP limits script sources and API/Cognito connections; production CORS allows only the frontend origin.
- Worker IAM permits scoped reads/writes; API IAM permits profile reads and signed document reads. Neither role can delete profiles/documents. Secrets Manager holds Neeto secrets; only the two functions read that specific secret. Secret values are absent from Terraform state because only secret containers are Terraform-managed.
- Download URLs must match configured hostnames and use HTTPS. DNS addresses are checked and pinned to prevent SSRF/rebinding. Redirects are revalidated and receive no Neeto API credential. Downloads have timeouts, a configurable size cap, PDF type/header checks, and memory-to-disk streaming. Filenames are sanitized and never determine the S3 key.
- Only JSON operation/status/ID/error-type events are logged. Do not enable request-body/header debugging in production. Local fixtures contain fictional identities only. The frontend's sample PDF is excluded from deployment.
- No automatic retention deletion exists. DynamoDB point-in-time recovery is enabled for profiles; S3 keeps only the current object. This is not a document backup strategy. Add an explicitly chosen backup/versioning policy if recovery of overwritten documents is required.

Keep Terraform state, `.env`, AWS credentials, logs, screenshots, and exported profiles out of Git. Local state may reveal infrastructure identifiers even though secret values are not stored. Rotate any credential exposed through an insecure channel. No passwords are committed or written to Terraform.

CloudFront forces the default generated-domain certificate to use its `TLSv1` security-policy setting, while modern browsers negotiate newer TLS. An optional custom domain/certificate uses `TLSv1.2_2021`. This Terraform conditional avoids perpetual drift; see [AWS ViewerCertificate documentation](https://docs.aws.amazon.com/cloudfront/latest/APIReference/API_ViewerCertificate.html).
